Water Vapor Transport

What is modeled

Water vapour is transported as an Eulerian grid field (mixing ratio), updated by a monotonic advection scheme. This module moves the H₂O field on the model grid using the resolved winds.

How it is implemented

Transport is implemented via a Walcek-style monotonic Eulerian advection step in sub_transwalcek(dx,dy,dz,um,vm,wm,hm), which internally uses a 1D advection operator sub_advec1d along each dimension.

! Key code concepts sub_transwalcek: Eulerian advection update for hm (H2O field) sub_advec1d: 1D monotonic advection operator used within Walcek transport hm: transported tracer field (water vapour mixing ratio)

Where it appears in the flow

This module appears in the following execution steps:

  • Step 14: Eulerian H₂O transport (advection)

Key references

  • Walcek (2000): Basis for the monotonic Eulerian advection scheme used for tracer transport.
  • Berger & von Zahn (2002): Model framework context for coupling transport concepts to the particle environment.

Eddy Diffusion (Kz)

What is modeled

Vertical turbulent mixing of water vapour is represented as a diffusion process acting on the Eulerian H₂O field. The diffusion strength is controlled by an eddy diffusivity profile (Kz), passed as turbkzz.

How it is implemented

Vertical diffusion is implemented in sub_diffu_h2o(hm,dz,turbkzz). The subroutine forms a diffusion operator and advances the H₂O field using a semi-implicit (Crank–Nicolson-type) formulation and solves the resulting tri-diagonal linear system using tridiag.

Parameter Value/Formula Description
Kz turbkzz(k) Eddy diffusivity profile used to compute diffusion coefficients in the vertical mixing step.

Where it appears in the flow

This module appears in the following execution steps:

  • Step 15: Vertical diffusion of H₂O (turbulence)

Key references

  • Berger & von Zahn (2002): Framework context for mixing/transport in the particle–environment system.

Photolysis & Solar Forcing

What is modeled

Water vapour is reduced by photodissociation driven by solar forcing. The model computes solar geometry and applies a photolysis tendency to the H₂O field using an external time series input (xlyman_obs).

How it is implemented

Solar geometry is handled in sub_zenit(ntg,itag1,ihemi). Photolysis is applied in sub_photolyse(mnudge,delta_t,ihemi,itag1,xlyman_obs), which uses the provided Lyman-α forcing series (xlyman_obs) to compute a photolysis rate at the top boundary and apply the effect to the model field.

Where it appears in the flow

This module appears in the following execution steps:

  • Step 12: Compute solar geometry and photolysis of H₂O
  • Step 16: Photolysis again

Key references

  • Berger & von Zahn (2002): Framework context for environmental forcing within the coupled system.

Ice Microphysics

What is modeled

Ice particles are treated as a Lagrangian ensemble embedded in an Eulerian background atmosphere. The module updates particle properties (e.g., radius) based on local thermodynamic conditions and interacts with the background H₂O field through condensation/sublimation coupling.

How it is implemented

The central routine is sub_tracertransp, which performs the combined particle microphysics + particle transport step. Lookup tables used by the microphysics (including Kelvin-related terms) are precomputed by sub_tabelle. The module uses shared state from common blocks/modules (common_eis, common_h2o, common_tab, etc.) and couples particle updates to the H₂O background field.

Where it appears in the flow

This module appears in the following execution steps:

  • Step 9: Precompute microphysics lookup tables
  • Step 17: Particle microphysics + particle transport step

Key references

  • Berger & von Zahn (2002): Core model framework, particle–environment coupling, and transport concepts.
  • Murphy & Koop (2005): Saturation vapour pressure formulation used for ice growth calculations (implemented via lookup tables).

Sedimentation

What is modeled

Particles experience a net vertical motion that includes gravitational settling (sedimentation) in addition to the resolved vertical wind. Sedimentation acts on the Lagrangian particle positions and directly shapes the vertical redistribution of ice.

How it is implemented

Sedimentation is applied as part of the particle update step inside sub_tracertransp, where particle positions are updated using the combined effects of background motion and particle-specific tendencies (including settling). The exact settling formulation is implemented in the particle step logic (not as a standalone subroutine in this file).

Where it appears in the flow

This module appears in the following execution steps:

  • Step 17: Particle microphysics + particle transport step

Key references

  • Berger & von Zahn (2002): Transport concepts for particles embedded in their modeled environment.

Turbulence vs Diffusion Mismatch

What is modeled

The model represents mixing using different numerical treatments for the two “carriers”: water vapour is a mass field updated by Eulerian diffusion/advection, while particles are updated as discrete Lagrangian entities. This creates an inherent mismatch when applying the same mixing intensity parameter (Kz) to both representations.

How it is implemented

For H₂O, turbulence is applied as vertical diffusion via sub_diffu_h2o(hm,dz,turbkzz). For particles, turbulent mixing is applied within sub_tracertransp as stochastic displacement/transport logic acting on particle positions. Both rely on the same eddy diffusivity input (turbkzz) but act on different state representations (Eulerian field vs Lagrangian particles).

Where it appears in the flow

This module appears in the following execution steps:

  • Step 15: Vertical diffusion of H₂O (turbulence)
  • Step 17: Particle microphysics + particle transport step

Key references

  • Berger & von Zahn (2002): Uses a shared mixing/transport context for the coupled particle–environment system.

Dust Reallocation Logic

What is modeled

Condensation nuclei (dust / meteoric smoke particles) are represented as a large discrete population. The model includes logic to keep the CN population stable over long integrations by redistributing or “reallocating” dust under certain conditions.

How it is implemented

The particle population is initialized by sub_init_staub(...). The “dust reallocation” itself is executed as a dedicated model step and is implemented in the particle system logic (not exposed as a separate subroutine name in this file’s subroutine list).

Where it appears in the flow

This module appears in the following execution steps:

  • Step 7: Initialize the 40 million dust particles (condensation nuclei)
  • Step 18: Dust “reallocation” to keep the CN population stable

Key references

  • Berger & von Zahn (2002): Particle environment framework in which CN populations are part of the modeled system.
